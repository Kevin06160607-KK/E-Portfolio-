1. Core Pillars of Web Security

Ensuring the CIA Triad (Confidentiality, Integrity, and Availability) across web applications

Confidentiality

Protecting sensitive user data (credentials, tokens, personal info) from unauthorized interception during transit and storage using strong encryption algorithms.

AES-256 TLS 1.3 Data Privacy

Integrity

Ensuring that HTTP requests, responses, and database records are not tampered with or altered by Man-in-the-Middle (MitM) attackers during transmission.

SHA-256 HMAC Digital Signatures

Authentication & Access

Verifying user and server identities reliably before granting access to protected web resources and APIs using multi-layered verification.

OAuth 2.0 JWT MFA / 2FA

2. Cryptography in Web Security (HTTPS / TLS)

How Public Key Infrastructure (PKI) and Hybrid Encryption secure browser-to-server communication

1. Client Hello

Browser sends supported TLS version & cipher suites to the web server.

2. SSL Certificate

Server responds with its CA-signed Digital Certificate & Public Key.

3. Key Exchange

Asymmetric crypto (ECDHE/RSA) establishes a shared symmetric session key.

4. Secure Tunnel

All HTTP traffic is encrypted using fast Symmetric AES-GCM cipher.

3. Major Web Threats & Countermeasures

Analysis of critical OWASP Web Security vulnerabilities and cryptographic/architectural defenses

Web Attack / Threat Severity Attack Mechanism Defense & Mitigation Strategy
SQL Injection (SQLi) Critical Injecting malicious SQL queries via unvalidated user input fields to bypass authentication or dump databases. Prepared Statements (Parameterized Queries), Input Validation, and Web Application Firewalls (WAF).
Cross-Site Scripting (XSS) High Injecting malicious client-side scripts into web pages viewed by other users to steal session cookies. Context-aware Output Encoding, Content Security Policy (CSP) headers, and HttpOnly cookie flags.
Cross-Site Request Forgery (CSRF) High Tricking an authenticated user's browser into executing unwanted actions on a trusted site. Anti-CSRF Cryptographic Tokens, SameSite=Strict cookie attributes, and Re-authentication.
Man-in-the-Middle (MitM) Critical Intercepting or altering unencrypted HTTP traffic between client and server on public networks. Enforcing HTTPS via HSTS (HTTP Strict Transport Security), TLS 1.3, and Certificate Pinning.
Broken Authentication Critical Compromising passwords, keys, or session tokens due to weak hashing or credential stuffing. Salted Password Hashing (Argon2 / bcrypt), Multi-Factor Authentication (MFA), and short-lived JWTs.

4. Essential HTTP Security Headers

Browser-level directives implemented in modern secure web servers

Content-Security-Policy

Restricts the sources from which scripts, styles, and images can be loaded, effectively neutralizing XSS and data injection attacks.

Header: CSP

Strict-Transport-Security

Forces web browsers to interact with the server exclusively over HTTPS connections, preventing protocol downgrade and SSL stripping attacks.

Header: HSTS

X-Frame-Options

Protects users against Clickjacking attacks by preventing the web page from being embedded inside unauthorized <iframe> elements.

DENY / SAMEORIGIN

Activity Summary & Learning Reflection

Through this E-Portfolio on Web Security under the course Cryptography and Cyber Security, I have explored the vital intersection between cryptographic primitives and real-world web application defense. Modern web security does not rely on a single barrier; instead, it operates on a Defense-in-Depth model.

By combining transport-layer encryption (TLS 1.3), strong password hashing (bcrypt/Argon2), secure coding practices against OWASP Top 10 vulnerabilities, and strict browser security headers, developers and security engineers can build resilient web ecosystems capable of safeguarding user privacy and organizational assets against evolving cyber threats.
